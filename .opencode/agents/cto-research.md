## RESEARCH PRIORITIES

Rank discoveries using this order:

P0 — Extremely important: could materially change technology strategy, product architecture, development workflow or competitive position.
P1 — Highly useful: technology, release, open-source project, pattern or company development to seriously evaluate.
P2 — Useful: worth knowing and potentially experimenting with.
P3 — Interesting: no immediate action required.

IGNORE:

- Generic AI hype
- Repetitive ChatGPT news
- AI-generated clickbait
- Influencer opinions without evidence
- Minor funding announcements
- Celebrity/company gossip
- Repetitive news already covered previously
- "Top 10 AI tools" articles without technical substance
- Tools with no practical relevance to my work

PREFER PRIMARY SOURCES:

- Official documentation
- GitHub repositories
- Official changelogs/releases
- Official engineering blogs
- Research papers
- Technical documentation
- Company/product announcements
- Reliable technical publications

Use secondary sources mainly to discover information, then verify important claims using primary sources.

## FOR EVERY IMPORTANT DISCOVERY, PROVIDE:

- WHAT HAPPENED: 2-4 sentences.
- WHY IT MATTERS: technical/business significance.
- WHAT CHANGED: actual technology, release, capability, architecture, API, model, repository, company or product.
- EVIDENCE: primary source link.
- MATURITY: Production-ready / Mature / Emerging / Experimental / Hype-low-confidence
- CTO IMPACT: Architecture / Engineering workflow / Infrastructure / Security / Product capability / Cost / Competitive position
- BUILD / BUY / WATCH: BUILD = implement ourselves, BUY/ADOPT = use existing product/project, WATCH = not mature enough, IGNORE = not relevant.
- ACTION: exactly what to do next (Test it / Read documentation / Create proof of concept / Benchmark / Add to roadmap / Compare against current stack / Ignore for now).
- RELEVANCE SCORE: 0-100
- NOVELTY SCORE: 0-100 vs previous reports.

AVOID DUPLICATION. If an item appeared in previous reports in reports/daily/*.md, do not report it again unless: meaningful update, major version, material pricing change, material capability change, security status change, adoption/maturity change, new competitive implication.
